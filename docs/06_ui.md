## 1. User Interface Overview & Golden Rules Application

Theo Mandel and Ben Shneiderman's Golden Rules of Interface Design are enforced across all screens:
1. **Consistency:** Standard color-coded status badges (`RESERVED` in blue, `ASSIGNED` in amber, `PICKED` in purple, `DELIVERED`/`FULFILLED` in green, `BLOCKED`/`FAILED` in red). Uniform header navigation bar with active user role badge.
2. **User Control & Reversibility:** Safe pre-pickup cancellation for customers; immediate emergency pause toggle for warehouse operators.
3. **Informative Feedback:** Synchronous toast notifications and progress meters indicating order reservation and physical robot transit coordinates.
4. **Error Prevention:** Form input validation preventing non-positive integers, negative stock deltas, or empty reason codes before submission.
5. **Clear Navigation:** Explicit role-filtered menus ensuring customers cannot see administrator menus.
6. **Visibility of System Status:** Live coordinates `(x, y)` and battery percentages of autonomous robots displayed directly on the operational grid.

## 2. Comprehensive Screen Design Specifications

### Screen 1: UI-01 – User Login & Authentication Screen
- **Target User:** All human users (Customer, Operator, Manager, Administrator, Auditor).
- **User Goal:** Authenticate identity to receive a role-scoped, cryptographically secure session.
- **Navigation:**
  - *Entry:* Default landing page `/login`.
  - *Exit:* Redirects to role-specific dashboard (`/orders` for Customer, `/operations` for Operator/Manager, `/audit` for Auditor/Admin).
- **Inputs:** Username (text input), Password (masked password input), Hidden Anti-CSRF Token.
- **Feedback:** Clear loading indicator during Argon2id/bcrypt verification; success toast upon login.
- **Error Handling:** Generic error message: *"Invalid username or password"* (prevents account enumeration attacks). If throttled due to 5 consecutive failures, displays *"Account temporarily rate-limited. Try again in 5 minutes."*
- **Security Considerations:**
  - Password field masked; copy/paste permitted but browser auto-complete disabled for passwords.
  - Submissions sent via HTTPS POST with `SameSite=Lax`, `HttpOnly`, and `Secure` cookie attributes.
  - Zero password echoing in server logs or HTML DOM.

### Screen 2: UI-02 – Customer Order & Tracking Screen
*(Direct mapping from examination requirement: 'Student Exam Screen')*
- **Target User:** Customer (`CUSTOMER` role).
- **User Goal:** Place product orders and track atomic fulfillment progress in real-time.
- **Navigation:** Accessible via `/orders` after customer login.
- **Inputs:** SKU selector (dropdown populated from active products), Quantity (numeric input bounded between 1 and 100), Hidden client-generated UUIDv4 `Idempotency-Key`.
- **Feedback:** Real-time stock availability check; visual step progress bar showing:
  `[1. Ordered] -> [2. Reserved] -> [3. Robot Picking] -> [4. Transit] -> [5. Delivered at Packing Area]`
- **Error Handling:**
  - Quantity <= 0 or > 100 rejected client-side with red border.
  - Server 409 Conflict displays clear banner: *"Item SKU-001 currently out of stock; order was not charged."*
- **Security Considerations:**
  - Customer ID derived exclusively from authenticated server session (prevents IDOR spoofing).
  - Customer cannot view other customers' orders or any robot management controls.

### Screen 3: UI-03 – Warehouse Management & Inventory Console
*(Direct mapping from examination requirement: 'Faculty Examination Management')*
- **Target User:** Warehouse Manager (`MANAGER` role) and Operator (`OPERATOR` role).
- **User Goal:** Inspect real-time stock balances across warehouse storage locations and execute authorized stock adjustments.
- **Navigation:** Accessible via `/inventory`.
- **Inputs:**
  - Read-only filter by SKU and location type.
  - *Stock Adjustment Form (Manager only):* Location ID, Product SKU, Signed Integer Quantity Delta ($\pm \Delta$), Mandatory Reason Text Box (minimum 10 characters).
- **Feedback:** Updated balance tables; visual indicator displaying `Available = On-Hand - Reserved`.
- **Error Handling:**
  - Preventing negative balance: Form disables adjustment if $\text{on\_hand} + \Delta < \text{reserved}$.
  - Operator attempting adjustment receives HTTP 403 Forbidden modal.
- **Security Considerations:**
  - Adjustments require re-authentication or explicit manager authorization token.
  - Every adjustment automatically appends an immutable entry to `inventory_movements` and `audit_events`.

### Screen 4: UI-04 – Fulfillment Results & Packing Dispatch View
*(Direct mapping from examination requirement: 'Results')*
- **Target User:** Customer (for own order) and Warehouse Manager (for all warehouse orders).
- **User Goal:** Verify delivery-to-packing confirmation, audit timestamps, and view exception logs.
- **Navigation:** Accessible via `/orders/{order_id}/result` or `/operations/results`.
- **Inputs:** Order search filter, Date range picker.
- **Feedback:** Printable delivery receipt showing: Order UUID, Customer Username, Items, Final Packing Bay Number, Delivery Timestamp UTC, Attributable Robot Serial.
- **Error Handling:** Invalid Order UUID yields generic 404 Not Found without database error leakage.
- **Security Considerations:**
  - Object-level ownership check prevents Customer A from viewing Customer B's delivery receipt.
  - Device security tokens and internal database primary keys are stripped from UI output.

### Screen 5: UI-05 – Robot Fleet & Dispatch Console
- **Target User:** Warehouse Operator and Manager.
- **User Goal:** Monitor 2D grid coordinates of active robots, view battery/heartbeat health, and dispatch tasks.
- **Inputs:** "Assign Next Task" button, "Emergency Pause" toggle button.
- **Feedback:** Live 10x10 ASCII/SVG warehouse grid map showing obstacles, storage bays, packing bays, and current robot positions.
- **Security Considerations:** No raw shell or unbounded command textboxes; all robot actions strictly allowlisted.

### Screen 6: UI-06 – Security Audit & Compliance Log
- **Target User:** Security Auditor and System Administrator.
- **User Goal:** Review immutable forensic logs of all authentication, stock, and robot actions.
- **Inputs:** Actor filter, Action type filter (LOGIN, ADJUSTMENT, ASSIGNMENT, DENIAL), Date picker.
- **Feedback:** Read-only paginated table with UTC timestamps, actor roles, outcomes, and IP addresses.
- **Security Considerations:** Zero edit or delete buttons exist in UI; database user lacks `UPDATE`/`DELETE` permissions on audit tables.
